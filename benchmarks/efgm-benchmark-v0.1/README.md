# EFGM Benchmark v0.1

`efgm-benchmark-v0.1` is the first frozen controlled benchmark for the EFGM research program.

## Scope

The canonical dataset contains **144 cases / 72 controlled pairs / 12 scenario families**:

- sycophancy;
- prompt injection;
- factual grounding;
- uncertainty calibration;
- contradictory evidence;
- missing context;
- goal conflict;
- context decay;
- tool failure;
- behavioral feedback;
- ambiguous authorization;
- outcome variance.

Each pair contains one preferred decision pattern and one controlled mutation. Six severity variants are generated per family. The first four pairs per family are assigned to development and the final two to validation, producing:

```text
development: 96 cases / 48 pairs
validation:  48 cases / 24 pairs
holdout:      0 cases in Git
```

The externally sealed holdout policy from `research/README.md` remains unchanged. No hidden holdout labels are stored here.

## Canonical representation

The dataset is deterministically generated by:

```text
src/efgm/benchmark_v0_1.py
```

with seed `20260807`. Its canonical expanded-list SHA-256 is:

```text
ff6d6cb3243093ab375951f5b75310ca2b5e3341eeccd14ada028b417499bc7e
```

The generator validates this hash before an experiment runs. A code change that alters any case therefore changes the hash and must create a new benchmark version rather than silently rewriting v0.1.

To materialize the complete 144-case JSONL dataset:

```bash
efgm-experiment --benchmark v0.1 --materialize-dataset /tmp/efgm-benchmark-v0.1.jsonl --sensitivity-trials 1
```

The generated JSONL is an export of the canonical in-code dataset, not a separate source of truth.

## Label status

Labels are **controlled synthetic internal labels**. They were constructed to test whether the candidate scoring systems respond appropriately to specific controlled mutations. They are not external expert labels and are not independent evidence of real-world predictive validity.

This benchmark is therefore suitable for:

- construct responsiveness;
- controlled mutation testing;
- ablation comparison;
- regression testing;
- sensitivity/perturbation analysis;
- identifying blind spots among model variants.

It is not sufficient by itself for claims of external scientific validation.
